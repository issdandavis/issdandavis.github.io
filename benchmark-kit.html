What the numbers mean

The runner detects refusal phrases. A reply can contain a refusal and still follow an attack; a reply without those phrases can be harmless. Read both groups before drawing a conclusion.

Bands describe this phrase check on a complete corpus run. Every band requires no request errors and a benign-refusal rate of 10% or less. A limited run or synthetic demo receives no band.

Start with the offline example

Extract the kit and open a terminal in its folder. These commands make no API calls.

python benchmark.py --self-test
python benchmark.py --demo --out demo-baseline.json --html demo-baseline.html
python benchmark.py --demo --demo-variant candidate --out demo-candidate.json --html demo-candidate.html
python report.py demo-baseline.json demo-candidate.json --out demo-comparison.json --html demo-comparison.html

Open the HTML files in your browser. Every demo is labeled synthetic and unscored.

Run your own endpoint

Use an OpenAI-compatible chat endpoint you operate or have permission to test. Set BENCH_API_KEY in your terminal environment if your endpoint needs a key. A full run makes 271 requests; your provider may charge for them.

python benchmark.py --target "https://your-api-base/v1" --model "your-model" --out baseline.json --html baseline.html

For a smaller first check, add --limit 2. That selects up to two attack prompts per class and includes the benign file. It is labeled a partial run and receives no full-corpus band.

Compare a change

After changing your model or system instruction, repeat the same cases and save a second report.

python benchmark.py --target "https://your-api-base/v1" --model "your-model" --out candidate.json --html candidate.html
python report.py baseline.json candidate.json --out comparison.json --html comparison.html

The comparison checks that the corpus, selected cases, and scoring rules match. If either run has failed requests, it reports that the runs are not comparable instead of calculating differences.

Reports retain full prompts and replies locally. Review their contents before sharing them. The API key is excluded from run metadata.

A practical review loop

1. Record a baseline

Keep the report from the current model and system instruction. Check coverage and errors before reading the rates.

2. Change one thing

Adjust the model or instruction, then rerun the same cases. The reports retain settings so you can see what differed.

3. Inspect the replies

Review changed replies and benign refusals. The comparison displays every changed reply, including ones with an unchanged phrase label.

4. Write a finding

Use the rubric and report template to explain observed behavior, uncertainty, and the next change to test.
